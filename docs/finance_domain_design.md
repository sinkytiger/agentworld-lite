# 금융 도메인: 공시 데이터를 다루는 멀티 에이전트 리서치 데스크

RPG 환경에서 측정한 것(역할 분담, 정보 전달, 인계, 인과 기여도)을 금융 분석 작업에 그대로 옮긴 도메인입니다. 에이전트 셋이 DART 공시 수치로 밸류에이션 지표를 계산하고 제출합니다. 에피소드 프로토콜, 궤적 형식, `evaluate`(CCE/PAC, 실패 유형), `report`, `pair-report`는 RPG와 같은 코드를 씁니다.

## RPG → 금융 대응

| RPG | 금융 | 구현 |
|---|---|---|
| 아이템 | 사실(fact): 공시에서 가져오거나 계산한 숫자 하나 | `finance/dataset.py` `Fact` |
| 인벤토리 | 에이전트별 노트북(사실 ID 목록) | 자기 노트북에 있는 사실만 쓸 수 있음 |
| 채집 | `fetch_financials`, `fetch_shares` | 수집 담당만 가능 |
| 제작 | `calculate` (사칙연산 수식) | 분석 담당만 가능 |
| 아이템 건네기 | `share_facts` (복사, 소모 없음) | |
| 검증기 체크포인트 | 제출 답안이 정답의 ±0.5% 이내 | `answer` 체크포인트 |
| 인과 그래프 | 수집 → 공유 → 계산 → 공유 → 제출 | 규칙 판정이 사실 출처를 따라감 |

역할 제한은 RPG와 같은 `restricted_tools`로 구현합니다.

| 역할 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|
| collector | 공시 조회, 공유, 채팅 | 계산, 제출 |
| analyst | 계산, 공유, 채팅 | 공시 조회, 제출 |
| reporter | 제출, 공유, 채팅 (시장 가격 보유) | 공시 조회, 계산 |

한 사람이 혼자 끝낼 수 없으므로 수집 → 분석 → 제출 사이의 인계가 반드시 필요합니다.

## 정직성 장치

- **숫자를 직접 입력할 수 없습니다.** 답안은 노트북의 사실 ID를 인용해야 하므로, 모든 제출값은 공시 원값과 계산식으로 추적됩니다.
- **사실 ID는 값이 바뀌지 않습니다.** 같은 이름으로 다른 값을 계산하면 `calc.x_2`처럼 새 ID가 생깁니다.
- **as-of 가드.** 기준일 이후에 제출된 보고서는 조회되지 않습니다. 미래 정보를 쓰는 실수를 막습니다.
- **안전한 계산기.** 수식은 숫자, 변수, `+ - * /`, 괄호만 허용합니다(AST 검사). 함수 호출과 속성 접근은 거부합니다.

## 과제

`agentworld_lite/finance/catalog.py`에 정의하고 `python -m agentworld_lite.finance make-tasks`로 `tasks/finance/`에 씁니다. 데이터는 `data/finance/sample/`의 **가상 회사**(샘플전자 999990, 샘플전자홀딩스 999980)입니다. 실제 기업이 아니며 수치도 지어낸 것입니다. 기준일은 2025-10-01입니다.

### f01 TTM PER

TTM 지배주주 순이익과 PER을 제출합니다.

- TTM 순이익 = 2024 연간 420억 − 2024 상반기 180억 + 2025 상반기 260억 = **500억 원**
- 시가총액 = 60,000원 × 보통주 2,000만 주 = 1.2조 원, PER = **24.0배**

흔한 실수는 모두 허용 오차(±0.5%) 밖의 오답이 되도록 데이터를 설계했습니다.

| 실수 | 결과 PER |
|---|---|
| 비지배지분 포함 순이익 사용 (530억) | 22.64배 |
| 별도 재무제표 사용 (440억) | 27.27배 |
| 직전 연간 실적만 사용 (420억) | 28.57배 |
| 상반기 × 2 (520억) | 23.08배 |
| 자기주식 차감 (1,950만 주) | 23.40배 |
| 우선주 포함 (2,100만 주) | 25.20배 |
| 2025 3분기 보고서 사용 | 조회 차단 (2025-11-14 제출) |

### f02 2분기 단독 영업이익률

보고서 손익은 연초부터의 누적이므로 2분기 단독 = 상반기 누적 − 1분기 누적입니다.

- 2분기 매출 = 4,400억 − 2,100억 = **2,300억 원**
- 2분기 영업이익 = 350억 − 160억 = 190억 원, 영업이익률 = **8.26%**
- 함정: 상반기 누적 마진 7.95%, 별도 기준 7.62%, 비율 단위 실수 0.0826

### 공유형 / 개인형 쌍

각 과제는 `_shared`와 `_private` 두 버전이 있고, 같은 문장의 위치만 다릅니다. `paired.py`의 동일 과제 비교 설계를 따릅니다.

- `_shared`: 계산 방법론과 데이터 계획이 모두 공유 문서에 있습니다.
- `_private`: 방법론과 데이터 계획은 analyst의 개인 브리핑으로, 가격 보유 사실은 reporter의 브리핑으로 옮깁니다. collector는 무엇을 조회할지 듣지 못하면 알 수 없습니다.

두 버전의 에이전트, 역할, 데이터, 목표, 검증기, 라운드 제한, 정답 시나리오는 같습니다. 궤적의 `matched` 필드 덕분에 `pair-report`로 바로 집계할 수 있습니다. `tests/test_finance.py`가 두 버전이 문장 위치 외에는 같은지 검사합니다.

## 실제 공시 데이터 (DART OpenAPI)

1. https://opendart.fss.or.kr 에서 무료 인증키를 직접 발급받습니다.
2. 환경변수에 넣습니다. 코드는 키를 출력하거나 파일로 저장하지 않으며, 오류 메시지에도 요청 URL(키 포함)을 넣지 않습니다.

```powershell
$env:DART_API_KEY = "발급받은 키"
```

3. 수집합니다. 종가는 DART에 없으므로 KRX 등에서 확인한 값을 `--price`로 넣습니다.

```bash
python -m agentworld_lite.finance fetch --company 005930 --periods 2024:FY 2024:H1 2025:Q1 2025:H1 --price 2025-09-30=<종가>
```

결과는 `data/finance/dart/<종목코드>.json`에 샘플과 같은 형식으로 저장됩니다. 정규화 규칙은 다음과 같습니다.

- 사용 API: `corpCode.xml`(회사 코드, 로컬 캐시), `fnlttSinglAcntAll`(전체 재무제표), `stockTotqySttus`(주식 총수).
- 손익 항목은 IS에서 찾고, 단일 포괄손익계산서만 있는 회사는 CIS에서 찾습니다. 계정은 XBRL `account_id`로 먼저 찾고, 없으면 한글 계정명으로 찾습니다.
- 분기·반기 보고서의 `thstrm_amount`는 3개월 실적이고 `thstrm_add_amount`가 누적입니다. 데이터셋에는 **누적**을 저장합니다. 사업보고서는 `thstrm_amount`가 연간입니다.
- 제출일은 접수번호(`rcept_no`) 앞 8자리입니다. 정정 보고서가 있으면 DART는 정정본을 돌려주므로 제출일이 원래보다 늦게 잡힐 수 있습니다(가드가 보수적으로 동작).
- 한계: 은행·보험 등 금융업은 매출 계정 체계가 달라 `revenue`가 비거나 다른 의미일 수 있습니다. 실제 과제를 만들 때는 정답값을 공시 원문과 대조해야 합니다.

## 실행

```bash
python -m agentworld_lite.finance validate
python -m agentworld_lite.finance run --agent llm --provider ollama --model llama3.2:3b --think off --settings full no_comm --seeds 7 8 9 --out runs/finance_llama32_3b
python -m agentworld_lite evaluate --run runs/finance_llama32_3b --judge rule
python -m agentworld_lite report --runs runs/finance_llama32_3b --out reports/finance.md
python -m agentworld_lite pair-report --runs runs/finance_llama32_3b --out reports/finance_pairs.md
```

`--agent scripted`는 정답 시나리오(성공 기준선), `--agent random`은 무작위 행동 기준선입니다.

## 첫 실행 결과 (2026-10-09)

과제 4개 × 채팅 허용(`full`)/금지(`no_comm`). 모델과 무작위 행동은 시드 7, 8, 9로 실행했습니다. 시드는 같은 과제의 반복입니다.

| 시스템 | 에피소드 | 성공 | 비고 |
|---|---|---|---|
| 정답 시나리오 (scripted) | 8 | 8 | f01 8라운드, f02 6라운드, 규칙 CCE 0.458 / 0.444 |
| 무작위 행동 | 24 | 0 | |
| `llama3.2:3b` (로컬, think off) | 24 | 0 | 계산 시도 1회, 제출 시도 3회(모두 실패) |

`llama3.2:3b`의 실패 양상은 다음과 같습니다.

- 행동 1,296회 중 708회(55%)가 실패했습니다. 그중 494회는 사실 ID 없이 호출한 `share_facts`였습니다.
- 채팅 148회 중 97회(66%)가 이전 메시지와 똑같은 문장이었습니다.
- 에피소드 24개 중 10개는 공시를 한 번도 조회하지 못했고, 10개는 조회만 하고 analyst에게 넘기지 못했으며, 4개는 analyst가 사실을 받았지만 계산을 완료하지 못했습니다.
- 2분기 과제에서 collector는 존재하지 않는 "Q2" 보고서를 87번 요청했습니다. 올바른 보고서(1분기·상반기)를 조회한 것은 공유형·채팅 허용 조건뿐이었고(31회), 나머지 세 조건에서는 0회였습니다. 로그에서 뚜렷한 원인은 찾지 못했습니다. 과제 하나, 소형 모델 하나의 관찰이라 정보 배치의 효과로 해석하지 않습니다.

실행 중 환경을 두 번 고쳤고, 위 결과는 고친 뒤 처음부터 다시 실행한 것입니다.

1. 소형 모델이 배열 인자를 `"[...]"` 문자열이나 파이썬 표기로 보내도 읽도록 했습니다.
2. 없는 보고서를 요청하면 기준일까지 제출된 보고서 목록을 알려 주도록 했습니다. DART 공시 검색 화면에서 볼 수 있는 정보입니다.

`gemma4:cloud`는 무료 사용 한도에 걸려 실행하지 못했습니다. 이 과제에서 협업이나 정보 배치를 비교하려면 기본 도구 사용이 되는 더 큰 모델이 필요합니다.
