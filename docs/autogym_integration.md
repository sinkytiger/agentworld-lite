## 1. AutoGym 요약

**핵심 아이디어**: 과제를 먼저 만들고 풀리는지 나중에 확인하는 대신, **해답 경로(청사진)를 먼저 확정**하고 그에 맞춰 환경·질문·검증기를 함께 만든다. 풀 수 있음이 생성 단계에서 보장된다.

| 단계 | 하는 일 |
|---|---|
| ① 청사진 초기화 | 시나리오(맥락·자원·접근 제약)와 페르소나(역할·전문성·선호)를 정하고, 생성 파라미터를 샘플링 |
| ② 청사진 구성 | 해답 공간(엔티티·속성·관계·조건), 검증 기준, 정보 의존성, 난독화 지도, 미끼를 정의. 최소 하나의 유효한 해답 경로를 유지 |
| ③ 미로 실체화 | 청사진을 실행 가능한 환경(자원·관계·권한·미끼)과 도구 인터페이스로 변환. 숨긴 정보는 도구로 찾을 수 있게 배치 |
| ④ 정답·검증기·수리 | 청사진의 해답 도출을 실제 환경에 실행해 정답을 계산하고, 거기서 검증기를 만든다. 실패하면 수리(자원 누락 / 도달 불가 기준 / 도출 불일치) |
| ⑤ 평가 | 과제당 롤아웃 8회, 검증기 점수 평균으로 난이도 구간: 어려움 < 0.30 ≤ 보통 < 0.80 ≤ 쉬움 |
| ⑥ 실패 분석 → 커리큘럼 | 능력 축별 성공률로 생성 분포 조정: 0.30 미만 축은 완화, 0.80 초과 축은 강화, 갱신 폭 제한 |

**생성 파라미터**
- 과제 위상 3단계: 직접 조회 → 다중 홉·다중 조건·목록 집계 → 교차 출처 비교·병렬 종합·복합 비교
- 능력 축 7종: 정량 계산, 빠짐없는 집계, 순위·비교, 시간 추론, 부정 검증("없음"이 정답), 암묵 기준, 교차 출처 조정. 축마다 "정말 그 능력을 쓰게 되는지" 확인하는 검증 술어가 붙음 (예: 집계 축은 결과 수가 페이지 크기보다 커야 함)
- 난독화 0.0–1.0: 0.0–0.3 영역·기간만 언급 → 0.4–0.6 목표만 → 0.7–0.9 업무 의도 1–2문장 → 1.0 청사진 엔티티 이름을 하나도 쓰지 않음
- 미끼 3채널: 페르소나(권한 경계·개인정보 의무), 콘텐츠(유사 레코드·낡은 값·충돌 버전), 도구(페이지네이션·잘린 응답·일시 장애·속도 제한)

**검증기 4종 + 3단계 판정**: 결과 정확성, 미끼 내성, 과정 품질, 개인화. 과정 판정 → 결과 판정 → 메타 판정이 [0,1] 보상으로 합친다. 정책은 "과정 좋음+결과 맞음이 최고, 결과만 맞으면 감점, 과정만 맞으면 부분 점수"이며, **구체 가중치는 공개되지 않았다.**

**답변 가능성 불변식**: 과제와 에이전트가 접근 가능한 환경을 합치면 검증 기준을 만족할 정보가 반드시 들어 있어야 한다. 어려움은 찾기·거르기·조정하기에서 와야 하고, 접근 불가능한 숨은 상태에서 오면 안 된다.

**결과**
- 생산성 짐: 350개 생성 중 297개(84.9%), 280개(80.0%) 유지. 설정 C2에서 Claude Opus 4.6은 61%가 보통·쉬움인 반면 gpt-oss-120b는 30%만 그렇다(모델 간 변별력).
- 실패 기반 시간 추론 짐: 100개 중 92개 유지. Opus 4.6에게 쉽지 않은 과제 10개는 모두 gpt-oss-120b에게도 어려웠다(목표한 약점을 정확히 겨냥).
- 비용: 전문가 작성 과제당 $500–1000·1–1.5시간 vs AutoGym $2–8·약 16분. 50과제 짐 기준 $25K–50K·2–4주 vs $100–200·54분.
- 한계: 인터페이스 현실감 78.0점, 미끼가 부자연스럽게 섞임, 자유 응답 과제는 여전히 LLM 판정에 의존, RL 실험은 8B 모델 500스텝뿐.

## 2. 왜 섞이나

| | AgentWorld | AutoGym |
|---|---|---|
| 질문 | 멀티에이전트가 **얼마나 잘 협업하나** | 검증 가능한 과제를 **어떻게 대량으로 만드나** |
| 강점 | 협업 전용 지표(CCE/PAC), 소통 실패 분류 | 풀 수 있음 보장, 난이도 조절 손잡이, 실패 기반 커리큘럼 |
| 약점 | 과제 200개를 사람이 만들어 확장·갱신이 느림 | 단일 에이전트 정보 탐색 과제 위주, 협업 축 없음 |

합치면 **실패한 협업 패턴을 겨냥해 더 어려운 협업 과제를 스스로 만들어 내는 멀티에이전트 훈련장**이 된다.

```
 생성 파라미터 ─▶ 청사진 ─▶ 과제(YAML) ─▶ 정답 실행·수리 ─▶ 인증된 과제
      ▲                                                      │
      │                                       에이전트 롤아웃 k회 (AgentWorld 프로토콜)
      │                                                      ▼
 가중치 갱신 ◀── 축별 성공률 + 실패 유형 ◀── 검증기 4종 · CCE/PAC · 실패 분류
```

## 3. 개념 번안: 단일 에이전트 → 멀티에이전트 **[설계]**

| AutoGym 개념 | 이 프로젝트에서의 번안 | 상태 |
|---|---|---|
| 도메인 시드 | 시뮬레이터 콘텐츠(레시피·자원·작업대·지역) | 구현 |
| 과제 위상 단계 | 목표 아이템의 레시피 깊이 1–3, 팀 구조 `chain`(제작 스킬마다 다른 에이전트) / `hub`(중앙 작업장 1명) | 구현 |
| 능력 축 | 협업 축: 아이템 인계 수, 원거리 합류(12칸 초과 이동), 정보 비대칭, 권한 비대칭, 작업대 제약, 수량, 팀 규모 | 구현(측정·기록) |
| 난독화 경사 | **분산 은닉**: 정보를 공유 문서 → 특정 에이전트의 개인 브리핑 → 월드 관측·도구 피드백으로 옮김 | 구현 |
| 답변 가능성 불변식 | 숨긴 사실은 반드시 누군가의 브리핑에 있거나, 관측(시야 8칸)·도구 오류 메시지(레시피 재료 안내)로 알 수 있어야 함 | 구현(배치 규칙으로 보장) |
| 정답 계산 | 청사진에서 컴파일한 정답 시나리오를 시뮬레이터에서 실제 실행 | 구현 |
| 수리 3종 | 자원 누락 → 노드 추가 / 위험 스폰 → 재배치 / 혼자 가능 → 권한 강화(채집꾼의 제작 금지) | 구현 |
| 미끼 3채널 | 페르소나·콘텐츠·도구 미끼 (§5) | 설계 |
| 검증기 4종 | 결과=SR/PSR, 과정=CCE/PAC+효율, 미끼 내성, 페르소나 준수 (§5) | 결과·과정은 기존 구현, 나머지 설계 |
| 난이도 구간 | k회 롤아웃 평균 보상으로 쉬움/보통/어려움 | 설계 |
| 커리큘럼 | 축별 성공률 + AgentWorld 실패 유형 → 가중치 갱신 (§6) | 설계 |

### 분산 은닉 4단계

| 구간 | 공유 문서 | 개인 브리핑 | 목표 문장 |
|---|---|---|---|
| low (0.0–0.3) | 레시피, 팀 명단, 인계 계획, 위치 전부 | 역할 제한 | 정확(대상·수량·위치) |
| mid (0.4–0.6) | 레시피, 팀 명단 | 자기 위치 정보 | 정확 |
| high (0.7–0.9) | 없음 | 자기 역할·자기가 쓰는 레시피·자기 위치 | 정확 |
| max (1.0) | 없음, 월드 가이드도 제거 | 자기 역할만. 성공 조건은 결과를 받는 사람만 앎 | 모호("원정 준비를 도와라") |

## 4. 1단계 구현 결과 (완료)

**구성**
- `agentworld_lite/blueprint.py`: 생성 파라미터 샘플링 → 레시피 트리 전개(필요량·제작 횟수·소비자) → 역할 생성(채집/제작/의뢰인, 채집꾼 분할로 팀 규모 조절) → 인계 목록 → 순환 의존 검사 → 배치(안전한 스폰, 작업대 옆, 건설 부지, 부족한 자원 노드 보충) → 과제 YAML(은닉 단계별 문서·브리핑, 검증기, 정답 시나리오)
- `agentworld_lite/gym.py`: 정답 실행 → 진단·수리(최대 3회) → 라운드 예산 → 축 기록 → 수율 통계
- `ScriptedAgent`: "N개 모일 때까지 반복", "목표 지점 도착까지 이동" 조건 지원 (정답 시나리오 컴파일용)
- CLI: `python -m agentworld_lite gen --n 30 --seed 7 --out tasks/gym`

**수율** (LLM 호출 없음, 30개 생성에 약 1초)

| 시드 | 시도 | 유지 | 수율 | 탈락 사유 |
|---|---|---|---|---|
| 1 | 60 | 56 | 93% | 팀이 2명뿐인 청사진 4건 (가죽처럼 재료를 시작 아이템으로만 받는 과제) |
| 7 | 30 | 28 | 93% | 같은 사유 2건 |

- 시드 7로 만든 28개는 기존 `validate` 경로에서 경고 0건으로 통과했습니다. 테스트(시드 1, 30회 시도)는 유지된 과제마다 정적 검증 통과, 정답 시나리오의 예산 내 성공, 대기만 하는 팀의 실패를 고정합니다.
- 정답 경로 평균 10~11라운드, 팀 평균 3.8명. 첫 시험의 수율 52%에서 생성기 수정 4가지(시작 아이템 선인계, 허브 구조물 분리, 2인 팀 분할, 협업 판정의 구매 경로 수정)로 93%가 됐습니다.
- **라운드 예산 [설계]**: `ceil(정답 라운드 × (2 + 은닉도))`, 20~55로 자름. 숨긴 정보가 많을수록 탐색·대화에 라운드가 더 듭니다. 정답만 40라운드를 넘으면 버립니다.

**논문과 다른 점 [설계]**: AutoGym은 LLM이 청사진을 짜지만, 여기는 레시피·맵을 코드가 알기 때문에 **프로그램으로 청사진을 짭니다**. 풀 수 있음이 확률이 아니라 구성으로 보장되고 비용이 0입니다. 대신 서사(시나리오·페르소나 문장)는 아직 템플릿이며, LLM 서사는 4단계로 미뤘습니다.

## 5. 2단계 설계: 미끼와 검증기 4종

### 미끼 (예산 n개, 채널별 샘플링)

| 채널 | 이 시뮬레이터에서의 형태 | 탐지 방법 |
|---|---|---|
| 페르소나 | 경로 밖 권한 제한(거래 금지), 금지 구역("던전 출입 금지"), 특정 동료와만 거래 | 위반 행동 수 |
| 콘텐츠 | 스킬이 모자란 유사 노드(철광석 옆 배치), 브리핑 속 낡은 좌표, 미끼 랜드마크, 이름이 비슷한 아이템(막대/판자) | 미끼 개체를 표적으로 한 행동, 낡은 좌표로의 이동 |
| 도구 | 작업대 첫 N회 "사용 중" 일시 실패, 정찰 결과 잘림, 라운드당 채팅 수 제한 | 장애 후 재시도 성공 여부 |

구현: 엔진에 장애 주입 훅을 추가하고, 미끼마다 id를 붙여 궤적에서 탐지합니다. 답변 가능성은 미끼를 켠 상태로 정답 시나리오를 다시 돌려 확인합니다.

### 검증기와 보상 [설계]

| 신호 | 정의 |
|---|---|
| 결과 O | 성공 여부(0/1)와 PSR |
| 과정 P | `0.5 × CCE + 0.5 × min(1, 정답 행동 수 ÷ 실제 행동 수)` |
| 미끼 내성 D | `1 − 미끼에 쓴 행동 수 ÷ 전체 행동 수` |
| 페르소나 S | `1 − 위반 수 ÷ 위반 기회 수` (청사진에 제약이 있을 때만) |

보상: `Q = mean(P, D, S)`일 때, 성공이면 `R = 0.6 + 0.4·Q`, 실패면 `R = 0.5·PSR·Q`.
논문의 비공개 정책을 다음 세 성질로 재현했습니다. 과정과 결과가 모두 좋으면 1.0. 결과만 맞고 과정이 나쁘면 0.6 이상으로 감점. 과정은 좋은데 결과가 틀리면 최대 0.5의 부분 점수.

**난이도 구간**: 과제당 k회 롤아웃(기본 4, 논문 8)의 평균 R로 어려움 < 0.30 ≤ 보통 < 0.80 ≤ 쉬움.

## 6. 3단계 설계: 실패 기반 커리큘럼 [설계]

1. 롤아웃을 생성 파라미터 차원별로 묶어 성공률 계산: 깊이, 팀 구조, 은닉 구간, 수량, 팀 규모, 미끼 채널
2. 난이도 순서가 있는 차원(깊이·은닉·미끼 예산·팀 규모): 해당 수준 성공률이 0.30 미만이면 확률 질량을 한 단계 쉬운 쪽으로, 0.80 초과면 한 단계 어려운 쪽으로 옮김
3. 순서가 없는 차원(팀 구조·축): 가중치를 `(1 − 성공률)`에 비례하게 움직여 약점에 집중
4. 갱신 제한: 반복당 가중치 변화 ±0.10 이내, 최소 0.05, 정규화 (논문의 "진동 방지용 제한")
5. **AgentWorld 실패 유형 → 생성 손잡이** (이 통합의 핵심 연결고리)

| 많이 나온 실패 유형 | 늘릴 과제 |
|---|---|
| 낡은·중복 메시지 | 깊이↑(긴 호흡), 인계 수↑ |
| 오인 | 팀 규모↑, 권한 비대칭↑ |
| 사실 오류 | 은닉 mid/high (좌표·수량을 말로 전해야 하는 과제) |
| 성급한 완료 선언 | 수량 2 이상, 체크포인트 다수 |
| 논리 불일치 | 작업대 제약·순서 의존이 깊은 과제 |
| 비실질 발화 | 생성 손잡이 없음 (프롬프트 쪽 문제) |

6. 생성 → 롤아웃 → 평가 → 갱신을 성능이 안정되거나 반복 한도에 닿을 때까지 반복

## 7. 4단계: LLM 서사와 품질 인증

- LLM이 청사진을 바꾸지 않는 범위에서 시나리오·페르소나 문장과 은닉 단계에 맞는 목표 문장을 씀. high 이상에서는 목표 문장에 좌표·도구 이름·수치가 새지 않았는지 규칙으로 검사
- 논문의 7개 항목 인증 점수(범위 준수, 근거성, 확장성, 과제·환경·인터페이스 현실감, 다양성)를 LLM 루브릭으로 선택 측정

## 8. 비용 감각

- 1단계(생성·인증): LLM 호출 없음.
- 2~3단계(롤아웃)가 비용의 대부분입니다. 과제 50개 × 롤아웃 4회 × 평균 3.8명 × 약 27라운드 ≈ 2만 호출.
