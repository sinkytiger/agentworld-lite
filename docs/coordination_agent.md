# 선택형 협업 에이전트 (`--coordination`)

기본 LLM 에이전트는 매 턴 새 관측으로 결정합니다. 이 옵션은 **같은 모델**을 감싸는 작은 로컬 제어기입니다. 가중치 학습이나 팀원의 비공개 상태 접근은 없습니다. 기준선 결과와 섞이지 않도록 별도 `--out` 디렉터리에서 실행하세요.

```bash
python -m agentworld_lite run --tasks tasks/paired --agent llm --provider ollama --model gemma4:cloud --only p07007_private --settings full --seeds 7 --out runs/p07007_base
python -m agentworld_lite run --tasks tasks/paired --agent llm --provider ollama --model gemma4:cloud --only p07007_private --settings full --seeds 7 --coordination --out runs/p07007_coord
```

제어기는 에이전트 **자신의** 성공한 채팅, 시도한 행동, 행동 결과만 기억합니다.

- 같은 수신자에게 같은 문장을 최근 8라운드 안에 다시 보내려 하면 한 번 다시 판단하게 합니다. 자신의 성공한 발신만 확인합니다. 동료가 보낸 같은 문장은 확인 응답일 수 있어 중복으로 보지 않습니다(정책 v2). 공백만 정규화하고 대소문자는 구분합니다. 사용자명과 아이템 ID가 대소문자를 구분하기 때문입니다. 두 번째 결정도 반복이면 그 턴에는 `wait`합니다. 실패한 채팅은 중복으로 간주하지 않습니다.
- 연속 3회 `wait`하면 관측에 대기 이유와 다음에 확인할 항목을 덧붙입니다.
- 보이는 HP가 가득 찼다면 `eat_food`를, 개인 브리핑에 금지된 도구가 있다면 그 도구를 이번 턴의 선택지에서 빼 둡니다. 모델이 그래도 해당 도구를 출력하거나 현재 좌표로 다시 이동하려 하면 한 번 다시 판단하게 합니다.
- 최근 4라운드 안에 같은 도구·인자로 실패했거나 아무 진전이 없었던 행동을 반복하려 하면 한 번 다시 판단하게 합니다. 두 번째 결정도 무효면 `wait`합니다.

에이전트당 추가 재판단은 한 에피소드에서 최대 8회입니다. 한도를 넘으면 무효 행동을 `wait`로 바꾸고 추가 호출을 하지 않습니다. 호출 수는 궤적의 `usage.calls`와 토큰 사용량에 포함됩니다. 제어기의 재판단·차단은 행동 `note`에 `duplicate_chat_*`, `ineffective_action_*`, `invalid_action_*`로 남습니다. 모델이 다른 유용한 행동을 택할지는 보장되지 않습니다. 특히 기본 채집·제작을 못 하는 소형 모델에는 메시지 억제만으로 성공률이 높아지지 않을 수 있습니다.

첫 로컬 동작 확인에서 `llama3.2:3b`는 `p07003_private`를 실패했고, 체력이 가득 찬 상태에서 `eat_food`를 반복했습니다. 무효 행동 재검토를 추가해 다시 실행했을 때 실패 행동은 44회에서 0회로 줄었으나, 56회 `wait`했고 과제는 여전히 실패했습니다. 재판단 때문에 모델 호출도 60회에서 120회로 늘었습니다. 그 뒤 현재 관측에서 확실히 무효인 도구를 아예 빼고 다시 실행하니 음식 낭비는 사라졌지만 메시지를 21회 보내고 과제는 여전히 실패했습니다. 보이는 팀 채팅도 중복 판정에 넣은 다음 실행은 채팅 15회, 실패 행동 0회였지만 과제는 역시 실패했습니다. 마지막 실행에서 모델 호출 112회(기본 행동 60회 포함)를 확인한 뒤, 에이전트당 추가 재판단 8회의 예산을 더했습니다. 이 단계별 실행은 구현 점검이며 성능 비교 결과가 아닙니다. 기준선과 제어 모드는 같은 청사진·시드에서 여러 번 실행하고 성공률뿐 아니라 실패 행동, 중복 채팅, 라운드, 모델 호출 수를 함께 비교해야 합니다. 클라우드 모델은 같은 시드에서도 응답 궤적이 달라질 수 있습니다.
