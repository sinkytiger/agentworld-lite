## 1. 한 줄 요약

MMORPG 샌드박스(Kaetram)에서 **3~20명의 LLM 에이전트**가 서로 다른 능력을 나눠 갖고 **채팅만으로 협업**해 장기 과제를 푸는 벤치마크입니다. 성공률뿐 아니라 "팀이 한 행동 중 실제로 성공에 기여한 비율"을 재는 **CCE(Causal Collaboration Effectiveness)** 지표를 제안합니다. 최고 모델(Gemini 3 Flash)도 성공률은 52%, CCE는 0.32에 그칩니다.

## 2. 문제의식

- 기존 멀티에이전트 벤치마크는 대개 **짧은 호흡**(몇 턴), **대칭적 역할**, 그리고 **성공/실패 이진 평가**에 머뭅니다.
- 실제 협업에서 중요한 것은 **비대칭 능력**(내가 못 하는 걸 동료가 함), **장기 계획 유지**, **정보 공유** 입니다. 같은 성공이라도 헛수고가 많았는지 효율적이었는지를 구분해야 합니다.
- 그래서 저자들은 (1) 역할이 비대칭이고 수십 라운드가 걸리는 과제와, (2) 행동 단위의 인과 기여도를 재는 지표를 함께 제시합니다.

## 4. 과제 설계

- **100개 수작업 과제** + **100개 증강 변형**(Claude Opus로 목표·스폰 위치·초기 아이템을 바꿔 생성한 뒤 사람이 검수).
- 8개 카테고리: 전투, 제작, 채집, 거래, 탐험, 생존, 건설, 협응.
- 과제 하나는 다음으로 구성됩니다.
  - 주 목표(반드시 협업이 필요하도록 설계)
  - 에이전트별 설정: 비대칭 역할·스킬·스폰 위치·시작 아이템
  - 라운드 예산: 25~55, 평균 38 (파일럿 실행으로 보정)
  - 과제별 컨텍스트 문서(게임 메커니즘·레시피)
  - **Python 검증기**: 최종 게임 상태를 검사해 성공 여부와 체크포인트(예: `Logs: 3/5, Kills: 0/3, All alive: True`)를 보고
- 예시(Task 01): 벌목꾼이 통나무를 베고 → 목공이 막대로 깎고 → 마법사가 구슬과 합쳐 지팡이를 만든다.

## 5. 평가 지표

### 5.1 성공률 계열
- **SR (Success Rate)**: 검증기 기준 성공 비율.
- **PSR (Partial Success Rate)**: 체크포인트 달성 비율의 평균.
- 행동 지표: 과제당 평균 라운드 수, 평균 채팅 수.

### 5.2 CCE — 이 논문의 핵심 기여

**정의**

- 𝒯 = 모든 에이전트의 모든 행동(도구 호출 + 채팅)
- 𝒮 = 목표를 *직접* 달성한 마지막 행동(들) ("success actions")
- 𝒞 = 𝒮 ∪ ancestors(𝒮): 인과 행동 그래프에서 𝒮로 가는 경로가 있는 모든 행동
- **CCE = |𝒞| / |𝒯|**, 에이전트별로는 **PAC_i = |𝒞 ∩ 𝒯_i| / |𝒯_i|**

**계산 절차 (역방향 추적)**

1. LLM에게 행동 로그를 주고 "목표를 직접 완수한 마지막 행동"을 고르게 함 (전제·준비 행동은 제외).
2. 마지막 라운드부터 첫 라운드까지 거꾸로, 라운드마다 LLM에게 묻는다: "이 라운드의 각 행동이 이미 기여로 판정된 행동을 인과적으로 가능하게(ENABLE) 했는가?"
   - 기여 기준: 이후 행동이 쓰는 자원을 생산 / 필요한 위치로 이동 / 조율에 도움되는 정보 전달 / 선행 단계
   - **포괄적(inclusive) 라벨링**: 조금이라도 도움되면 기여로 판정 → CCE는 "진짜 유용한 행동 비율"의 **상한**.
3. 판단 단위를 "협업이 좋았나?" 같은 주관적 점수가 아니라 "새우 낚시가 이후 새우 전달을 가능하게 했나?" 같은 **이진 인과 판단**으로 쪼개서 객관성을 확보.

**검증**: GPT-4.1 판정과 사람 판정 84건을 비교해 원시 일치율 82%, Cohen's κ = 0.64.

**[추론] 실패 에피소드의 CCE**: 실패하면 𝒮가 비므로 정의상 𝒞 = ∅이고 CCE = 0입니다. 논문 수치도 이 해석과 맞습니다. Gemini는 0.320 / 0.52 ≈ 0.62, DeepSeek는 0.125 / 0.20 ≈ 0.63으로, "성공 에피소드 내 CCE"가 모델 간에 비슷하게 약 0.6이 됩니다. 따라서 논문의 CCE 격차는 상당 부분 **성공률 격차**를 반영한다고 읽을 수 있습니다. 이 파이프라인은 그래서 `CCE`(실패=0)와 `CCE | success`를 따로 보고합니다.

## 6. 실험 결과

### 6.1 주요 결과 (메인 100과제, 블랙박스)

| 모델 | SR | 비고 |
|---|---|---|
| Gemini 3 Flash | **52.0%** | CCE 0.320 (최고) |
| Claude Haiku 4.5 | 45.0% | |
| GPT-5 Mini | 36.0% | 과제당 채팅 44.1회로 최다 |
| DeepSeek R1-70B | 20.0% | CCE 0.125, 채팅 7.5회로 최소 |

- **소통의 역설**: 말이 가장 많은 모델(GPT-5 Mini)이 성공률은 3위입니다. 말을 너무 적게 해도(DeepSeek) 실패합니다. 대화량이 아니라 **대화의 질**이 중요합니다.
- 카테고리별: 생존이 가장 쉽고(50~100%), 협응(0~50%)·건설(0~60%)·거래(8~46%)가 가장 어렵습니다. 공통점은 **다단계 공급망**과 **동시성**이 필요하다는 것입니다.

### 6.2 기준선 (Table 3, Gemini 3 Flash)

| 설정 | SR | 평균 라운드 | 평균 채팅 |
|---|---|---|---|
| 랜덤 행동 | 5.7% | 34.1 | 8.3 |
| 공유 계획 + 소통 없음 | 17.6% | 30.7 | 0.0 |
| 소통 없음 | 22.9% | 32.0 | 0.0 |
| 단일 에이전트 | 28.6% | 28.0 | 0.0 |
| **기본 멀티에이전트 (블랙박스)** | **52.0%** | 26.4 | 11.0 |
| 오라클 소통 (한 에이전트가 모든 메시지를 봄) | 60.0% | 25.2 | 7.9 |

논문 캡션은 기본 멀티에이전트가 Table 2의 메인 결과(100과제)와 같은 설정이라고 밝힙니다. 기준선들이 정확히 어떤 과제 집합에서 측정됐는지는 원문에서 한 번 더 확인하는 것을 권합니다.

해석: 채팅을 막으면(22.9%) 혼자 푸는 경우(28.6%)보다도 낮아지고, 기본 설정(52.0%)은 그 두 배 이상입니다. 오라클 소통(60.0%)과의 격차 8%p는 소통을 더 잘하면 얻을 수 있는 여지입니다.

### 6.3 설계 요소 소거 (Table 4, 35과제 부분집합, Gemini 3 Flash)

| 설정 | SR | 평균 라운드 | 평균 채팅 |
|---|---|---|---|
| **전체 AgentWorld** | **54.3%** | 18.8 | 4.7 |
| 비대칭 역할 제거 | 45.7% | 20.2 | 4.5 |
| 장기 호흡 제거 | 37.1% | 8.7 | 2.4 |
| 스폰 무작위 | 51.4% | 19.5 | 4.6 |
| 문서 제거 | **29.4%** | 30.7 | 3.9 |

이 표는 35과제 부분집합에서 측정한 별도 실험이라, Table 3의 수치(예: 52.0%, 22.9%)와 섞어 비교하면 안 됩니다. 표 안에서 보면 가이드 문서를 빼면 성공률이 거의 반으로 줄어(54.3% → 29.4%) **게임 지식 접근**이 큰 병목입니다.

### 6.4 실패 유형 분류 (궤적 분석)

| 유형 | 비중 | 예 |
|---|---|---|
| 낡은·중복 메시지 (Stale & Redundant) | **37.7%** | 이미 끝난 일을 언급, 해결된 질문 반복 |
| 오인 (Misidentification) | 16.4% | 자기 역할 착각, 엉뚱한 동료에게 요청 |
| 사실 오류 (Factual Error) | 14.8% | 틀린 아이템명·좌표, 거짓 준비 완료 보고 |
| 성급한 완료 선언 (Premature Completion) | 11.5% | 검증 전에 "끝났다" 선언 |
| 비실질 발화 (Non-Material) | 11.5% | 행동으로 이어지지 않는 잡담 |
| 논리 불일치 (Logical Inconsistency) | 8.2% | 불가능한 전략, 모순된 지시 |

가장 큰 실패 원인은 **공유 상태의 동기화 실패**(낡은 정보)입니다. 에이전트가 "지금 팀이 어디까지 왔는지"를 계속 추적하지 못합니다.

## 7. 비판적 검토

1. **판정자 의존성**: CCE는 LLM 판정자(GPT-4.1)에 의존합니다. κ = 0.64는 "상당한 일치" 수준이지만 완벽하지 않고, 포괄적 라벨링 때문에 체계적으로 높게 나옵니다(상한).
2. **CCE와 SR의 혼재**: 실패를 0으로 두면 CCE가 SR과 강하게 상관됩니다([추론], §5.2). "성공했을 때 얼마나 효율적이었나"를 보려면 조건부 CCE를 따로 봐야 합니다.
3. **평가 모델 구성**: 경량·중형 모델(Flash, Haiku, Mini, 70B) 위주라, 최상위 모델에서 같은 결론이 나올지는 별도 확인이 필요합니다.
4. **턴제 단순화**: 재현성을 위해 실시간 MMORPG를 턴제로 바꿨습니다. 실시간 동시성 문제(경합, 지연)는 다루지 않습니다.
5. **세부 구현은 공식 코드에서 확인 필요**: 논문 본문만으로는 도구 13개의 전체 목록과 관측 포맷 원문을 알 수 없습니다. 정확한 재현은 공식 저장소([openagents-org/agentworld](https://github.com/openagents-org/agentworld))를 기준으로 해야 합니다.
